# Mechanism Clarity: Explicit Chains, Examples, Symbols, Distinctions

## 5. Never Hide the Mechanism Behind Vague Language

Banned vagueness: "processes the data," "makes a decision," "learns from
experience," "stores the information." These conceal the reasoning.

Always answer: What enters? What changes? What operation happens? What
comes out? Why does that output follow?

```text
Input
  ↓
Operation
  ↓
Intermediate result
  ↓
Next operation
  ↓
Output
```

## 6. Make Abstract Ideas Concrete

- Processes: initial state → step 1 → new state → step 2 → new state.
- Math: general equation → meaning of each term → insert numbers →
  calculate → interpret.
- Systems: Component A → Component B → Component C.
- History: condition → event → reaction → consequence → long-term effect.
- Programming: input → function → transformation → output.

Examples must demonstrate the mechanism, not merely illustrate the topic.

## 7. Use One Coherent Example for Difficult Concepts

Do not switch examples mid-explanation. Pick one small example and reuse
it for: initial situation → basic mechanism → advanced mechanism →
exception → final result. The learner watches one thing evolve instead of
many disconnected snapshots.

## 8. Explain Every Important Symbol, Term, or Component

Never introduce notation without defining it. For `F = ma`: F = force,
m = mass, a = acceleration — then the relationship ("fixed mass: more
force → more acceleration"). For each term give: what it means, what role
it plays, what it is not. Critical when terms sound similar.

## 9. Derive Equations Instead of Dropping Them In

Question → what quantities matter → what relationship should exist →
equation → meaning of each term → numerical example → interpretation.
For `a* = argmax_a f(a)`: what `a` is, what `f(a)` is, what `argmax`
means, what the equation asks, how to evaluate it with real values. The
learner must know what the equation *does*.

## 10. Explicitly Separate Similar Concepts

Most confusion is two concepts with different roles merged into one.

| Concept A | Concept B |
|---|---|
| What it is | What it is |
| Its purpose | Its purpose |
| What information it uses | What information it uses |
| What it changes | What it changes |
| What it produces | What it produces |

Then show interaction: A does X → B receives it → B does Y → combined
system produces Z. Understanding each part alone ≠ understanding the
relationship.
