# Teaching Moves: Confusion, Validation, Analogy, Visuals, Domains

## 11. When the Learner Is Confused, Diagnose

Never repeat the same explanation louder. Find the collision:

> "The difficult part here is not X. It is the relationship between X and Y."

Then: X does … / Y does … / the connection is … — then one concrete
example. Locate the missing link in the mental model.

## 12. Validate the Learner's Existing Reasoning

Do not replace their explanation wholesale. Break it down:

```text
Your understanding:
    Part A ✓
    Part B ✓
    Part C needs adjustment
```

Then correct only C: "Your overall picture is correct. The part that needs
adjustment is…" Preserve correct knowledge.

## 13. Use Analogies as Bridges, Not Substitutes

Structure: analogy → intuition → actual mechanism. Example: "An index is
like a book index — but unlike the book, the database stores a structured
data structure mapping values to records." Drop any analogy that gets more
complicated than the concept or smuggles in false assumptions.

## 14. Use Visual Thinking

Match diagram to relationship: process (A ↓ B ↓ C ↓ D), hierarchy (tree),
decision (condition → Yes/No branches), network (input → processing →
output with feedback arrow), causal chain (cause → mechanism → immediate
effect → long-term consequence). Clarify, don't decorate.

## 15. Track Changing Quantities

Show before/after, never just direction:

```text
Before: x = 10
Operation: x = x + 5
After: x = 15
```

For multiple variables use a Before/After table (A, B, C columns).

## 16. Distinguish State, Process, and Result

```text
STATE — What is true right now?
PROCESS — What operation changes the state?
RESULT — What is true afterward?
```

Applies everywhere: physics (position → force → new position), computing
(memory → instruction → new memory), economics (conditions → shock → new
equilibrium), history, biology.

## 17. For Historical/Causal Topics, Explain Chains, Not Lists

Background conditions → pressures → trigger → immediate response →
escalation → outcome → long-term consequences. Separate background
conditions, immediate causes, contributing factors, triggers,
consequences, and interpretations. Correlation ≠ causation; when
interpretations differ, name them.

## 18. For Technical Subjects, Separate Theory From Implementation

Conceptual model → formal/mathematical model → algorithm → implementation
→ testing → application. Never present one implementation choice as the
concept itself: "The concept requires X. This implementation chooses Y."

## 19. For Research Questions, Separate Evidence From Interpretation

Label every claim: established fact / source claim / interpretation /
inference / hypothesis / proposed approach. What study A did ≠ what study
B did ≠ what would be reasonable to try. Never present a proposal as a
result.
